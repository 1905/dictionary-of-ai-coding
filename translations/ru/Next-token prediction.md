---
title: "Предсказание следующего токена"
description: "Модель выбирает следующий токен по контексту, добавляет его и повторяет процесс. Так создаётся любой ответ."
---

То, что [модель](./Model.md) действительно делает. Получив [контекст](./Context.md), она выбирает один следующий [токен](./Token.md), добавляет его и запускается снова. Любой результат — предложение, [вызов инструмента](./Tool%20call.md), файл на тысячу строк — строится по одному токену. Другого режима работы у модели нет.

Каждый шаг одинаков: токены из [контекстного окна](./Context%20window.md) проходят через [параметры](./Parameters.md), и для каждого токена словаря вычисляется вероятность. Один вариант очень вероятен, другой — меньше. По этим вероятностям выбирается токен, добавляется к тексту, и цикл повторяется с чуть более длинным контекстом. Именно выбор объясняет, почему один промпт даёт разные ответы: [недетерминированность](./Non-determinism.md) встроена в механизм.

Этот механизм объясняет поведение, которое иначе кажется странным. Перед выводом модель не проверяет, _истинен_ ли токен, — только насколько он _вероятен_. Отсюда [галлюцинации](./Hallucination.md). Каждый выданный токен уже принят, поэтому уверенное первое предложение способно направить весь ответ по неверному пути. А поскольку [выходные токены](./Output%20tokens.md) создаются строго последовательно, скорость генерации ограничивает скорость работы любого [агента](./Agent.md).

_Пример:_

«Как агент “решает” вызвать инструмент?»

«В основе всё то же предсказание следующего токена. Вызов инструмента — структурированная строка, которую [обвязка](./Harness.md) извлекает из выходного потока».
