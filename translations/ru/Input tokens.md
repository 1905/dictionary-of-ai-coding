---
title: "Входные токены"
description: "Токены, которые обвязка отправляет в каждом запросе. Обычно стоят дешевле выходных токенов."
---

[Токены](./Token.md), которые [обвязка](./Harness.md) отправляет в каждом [запросе к провайдеру](./Model%20provider%20request.md): [системный промпт](./System%20prompt.md), история разговора, [результаты инструментов](./Tool%20result.md) — всё, что [модель](./Model.md) читает перед ответом. Они стоят дешевле [выходных токенов](./Output%20tokens.md), потому что требуют меньше вычислений.

При разработке с [AI](./AI.md) входные токены составляют большую часть счёта. Модель [не хранит состояние](./Stateless.md), поэтому каждый [ход](./Turn.md) заново отправляет всю [сессию](./Session.md): первое сообщение, каждый ответ и результат инструмента. На пятидесятом ходу вход содержит предыдущие сорок девять. Один запрос может выдать несколько сотен токенов и при этом повторно отправить сто тысяч токенов истории.

[Кэш префикса](./Prefix%20cache.md) снижает стоимость: история, точно совпадающая с предыдущим запросом, оплачивается как дешёвые [кэшированные токены](./Cache%20tokens.md). Если вход всё равно дорог, уменьшите повторно отправляемые данные: [очищайте](./Clearing.md) или [сжимайте](./Compaction.md) контекст между задачами.

_Пример:_

«Счёт большой, а [агент](./Agent.md) почти ничего не пишет».

«Дело во входных токенах: каждый ход отправляет всю сессию. Без кэша префикса ты снова платишь за историю в каждом запросе».
