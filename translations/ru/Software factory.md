---
title: "Фабрика разработки"
description: "Сессии агентов запускаются событиями или расписанием, чтобы человек участвовал только там, где нужно его решение."
---

Система работы, в которой [сессии](./Session.md) [агентов](./Agent.md) запускаются событиями: созданием задачи, расписанием, сбоем CI, завершением другой сессии. Человеку не нужно запускать каждую. Больше работы выполняется [AFK](./AFK.md), а внимание остаётся для решений [с участием человека](./Human-in-the-loop.md).

Без фабрики каждую сессию кто-то начинает вручную. Даже автономная работа ждёт, пока человек откроет сессию, укажет [задачу](./Ticket.md) и запустит её. Команды хотят выполнять больше. Фабрика убирает человека из запуска сессий, но не обязательно из остальных шагов.

Типичные события:

| Событие                        | Запускаемая работа                    | Пример                                                                                       |
| ------------------------------ | ------------------------------------- | -------------------------------------------------------------------------------------------- |
| Задача создана или помечена    | Исследование, исправление, реализация | Метка `ready-for-agent` запускает сессию, открывающую PR                                     |
| Расписание cron                | Регулярное обслуживание               | Исправление одного правила линтера за ночь                                                   |
| Сбой CI или сигнал мониторинга | Диагностика и попытка исправления     | Неудачная сборка main запускает поиск сломавшего коммита                                     |
| Завершение другой сессии       | Следующий этап                        | PR запускает [автоматическое ревью](./Automated%20review.md), замечания — сессию исправлений |

Фабрика не обязана охватывать весь процесс. Одна задача cron с одним типом работы и проверяемым PR уже подходит. Начинать узко полезно: маленькие похожие PR позволяют оценить доверие до расширения автоматизации.

Люди могут участвовать в любой точке: писать задачи, ставить метки, утверждать план, выполнять [ревью](./Human%20review.md) перед слиянием. Выбор этих точек — главный проектный вопрос. Если в кодовой базе или её части никто не читает результат фабрики, это [dark factory](./Dark%20factory.md).

_Пример:_

«Кто исправил все нарушения `no-floating-promises`?»

«Фабрика. Ночью cron выбирает правило и открывает PR. Утром я проверяю».
