Agent experience — насколько [окружение](./Environment.md) помогает [агенту](./Agent.md) хорошо работать с кодом. Аналог [DX](./DX.md), ориентированный на агента. Если один агент с той же [моделью](./Model.md) и [обвязкой](./Harness.md) хорошо работает в одном репозитории и плохо в другом, причина обычно в AX. Хочется обвинить модель или переписать промпт, но исправление чаще нужно в репозитории.

Три основных измерения:

| Направление             | Хороший AX                                                                                                                                                                                                     |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Автоматические проверки | Быстрые детерминированные [проверки](./Automated%20check.md): типы, тесты, линтер, по которым агент исправляется без человека                                                                                  |
| Архитектура             | Предсказуемая структура, много поведения за небольшими интерфейсами, ясные имена; не нужно читать всё                                                                                                          |
| Свободный контекст      | Краткие [AGENTS.md](./AGENTS.md.md), [навыки](./Skill.md) и [инструменты](./Tool.md), оставляющие большую часть [окна](./Context%20window.md) задаче и удерживающие [зону уверенной работы](./Smart%20zone.md) |

AX и DX пересекаются: проверки и понятная архитектура полезны обоим. Но человеку доступны устные знания, ожидание медленного CI и «спроси Сару про биллинг». Агенту — нет. Подсказки IDE и красивые панели не заменяют ошибок в виде текста [результата инструмента](./Tool%20result.md). У проекта может быть хороший DX и плохой AX.

_Не стоит:_ считать AX синонимом DX: аудиториям нужны разные улучшения.

_Пример:_

«В репозитории API агент пишет хороший код, во фронтенде — плохой».

«У API строгие типы и быстрые тесты. Во фронтенде их нет, зато сорок постоянно загруженных навыков. Это разница AX, а не модели».
