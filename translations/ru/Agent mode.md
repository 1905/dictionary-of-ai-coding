Настройка поведения [агента](./Agent.md) во время работы: объединяет [режим разрешений](./Permission%20mode.md) и инструкции, добавляемые в [системный промпт](./System%20prompt.md). Обычный режим спрашивает о рискованных вызовах. **Plan mode** запрещает правки и направляет на исследование. **Accept-edits** автоматически разрешает правки. **Bypass permissions**, также **YOLO mode**, разрешает всё.
Переключать можно [посреди сессии](./Session.md).

Именно объединение отличает режим от простой настройки разрешений. Разрешения лишь решают, какие [вызовы инструментов](./Tool%20call.md) пропустить. Без инструкций агент хочет записать файл, получает отказ и ищет обходной путь. Инструкции меняют намерение: режим планирования объясняет, что сейчас нужно читать, спрашивать и предлагать. Запрет и направление работы совпадают.

На практике режим меняют вместе с уровнем доверия. Одну задачу можно начать с планирования, первые деликатные правки выполнять с подтверждением, затем перейти к accept-edits, а для [AFK](./AFK.md) внутри [песочницы](./Sandbox.md) — к bypass. Разговор продолжается с того же места, но с новыми разрешениями и инструкциями. Если вы всё одобряете не глядя, режим строже вашего доверия. Если постоянно отклоняете изменения — свободнее.

_Названия у поставщиков:_ Claude Code называет их «permission modes», Codex — «approval modes». Оба названия появились до объединения с инструкциями поведения.

_Пример:_

«Он правит файлы, хотя мне нужен только план».

«Включи plan mode: запись будет запрещена, работа останется исследовательской».

«А для запуска без меня?»

«Bypass, но только внутри песочницы».
