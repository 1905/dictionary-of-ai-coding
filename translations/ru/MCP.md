**Model Context Protocol.** Протокол подключения внешних серверов инструментов к [обвязке](./Harness.md). Так [агент](./Agent.md) получает [инструменты](./Tool.md) сверх встроенного набора. Агент не «вызывает MCP»: он вызывает инструмент, который обвязка получила от сервера MCP. Протокол также предоставляет ресурсы — данные только для чтения — и промпты — повторно используемые шаблоны. Основное применение — инструменты.

Протокол решает задачу интеграции. Без стандарта каждой обвязке нужна своя реализация доступа к Linear, Slack и базе данных. С MCP интеграцию один раз пишут как сервер, и её использует любая совместимая обвязка. Она подключается к серверу, получает список инструментов, и те становятся доступны агенту наряду со встроенными.

Цена — [контекст](./Context.md). Каждый инструмент приходит с именем, описанием и схемой параметров. [Модель](./Model.md) может вызвать только известный ей инструмент. Простой подход загружает все определения в [окно](./Context%20window.md) заранее. Несколько больших серверов — и ещё до первого сообщения [сессия](./Session.md) содержит тысячи [токенов](./Token.md) схем, расходуя [внимание](./Attention%20budget.md) на ненужные задаче инструменты.

Многие обвязки уменьшают эти расходы через поиск инструментов. Вместо полных определений контекст содержит [указатель](./Context%20pointer.md): агент ищет по имени или назначению и загружает определение при необходимости. Если ваша обвязка так не умеет, начальная стоимость сохраняется. Подключайте только нужные проекту серверы.

_Пример:_

«Агенту нужно читать задачи из Linear».

«Подключи сервер Linear MCP. Он предоставляет API Linear в виде инструментов, и отдельные обёртки писать не придётся».
